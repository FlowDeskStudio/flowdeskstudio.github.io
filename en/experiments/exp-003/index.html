EXPERIMENT #003 / COMPLETE

How far can one sentence
take an AI build?

I asked for 15 things to find the limit.
The limit was not found.

2026.10.09 CLAUDE OPUS 5.5 15 BUILDS

The result first.

I gave an AI one sentence per subject and had it build 15 games and apps. No retries and no fixes. The AI was also told not to run or test what it wrote.

All 15 met every checkpoint that had been set before building.

Difficulty rose in five levels, from a memory card game to a 3D sandbox and a one-hour RPG. The plan assumed things would start breaking somewhere, and even set a rule for stopping early. Within these 15, nothing broke.

What I wanted to find out

Claims that AI can build a game or an app from a simple request are everywhere online. Most of them show a handful of examples. In the searching done for this experiment, no record turned up that counted results under one fixed set of conditions while raising the difficulty.

So this experiment fixed the conditions and counted. There was one question.

With a one-sentence request, how hard a thing can an AI build?

Claude Code did the building. A human, the person who runs this site, did the hands-on judging.

Conditions

  • One request per build. No retries, no follow-up requests, no fixes by a human or an AI
  • Every request used the same wording, with only the subject swapped in
  • Each build ran in a fresh conversation, so nothing carried over from another subject
  • The AI saved what it wrote without running or testing the code
  • The output was a single HTML file with no external assets, no network requests and no browser storage
  • Three checkpoints per subject were set before building, so the bar could not move after seeing the result

There were three possible verdicts. "Usable" means all three checkpoints were met. "Runs but not usable" means it opens and runs but a checkpoint is missing. "Does not run" means it cannot be opened or started, or breaks right away. Fun and difficulty balance were not part of the verdict.

The 15 subjects were split into five levels of three. Level 1 was staples that are often shown online as things AI has built. From there the levels moved to subjects with many rules, technically demanding subjects, subjects that need an opponent or scale, and subjects that seemed unreasonable to ask for.

Each one runs inside a frame that cannot reach the network, so nothing you type or draw is sent anywhere. Most assume a computer, and the accuracy of the content, such as the quiz answers, has not been checked.

The other five (two falling-block puzzles, the 3D sandbox, the one-hour RPG and the RPG-style battle) are not published. Their look, mechanics or wording were judged too close to well-known existing works. A one-sentence request can lead an AI to return something modeled on a famous title. That was one more thing this experiment showed.

How deep the checks went

"Usable" means a human actually operated the build and confirmed the three checkpoints. For the checkpoints that only show up at the end, this is what was done.

  • Two-player shogi: illegal moves such as a second pawn on the same file were tried and were blocked
  • Shogi against the computer: one full game was played to checkmate
  • Roguelike: both taking the stairs to the next floor and dying to end the run were seen
  • RPG: the town, the dungeons and combat were checked, and the game was played through the boss to the ending

Many other things were not checked at all: whether the builds hold up over long use, whether the finer shogi rules such as repetition are correct, whether the games are well balanced, and whether all of the roughly 100 functions the spreadsheet is reported to have are correct. These are outside the verdict.

The ten-build pilot

The day before the main run, there was a pilot of ten staple subjects: a falling-block puzzle, whack-a-mole, a memory game, a shooter, an RPG-style battle, a quiz, a coloring app, a weekly task manager, a birthday card maker and a product landing page.

All ten opened and ran. This was the reaction after trying them (translated from Japanese).

They are all well made. Releasing them as games would still take repeated test play and difficulty tuning. Even so, it is hard to believe each one came from a single request.

The pilot is not counted in the 15 above because its conditions were different. The AI was not stopped from checking its own work before saving, and how much it did varied by subject, from writing only to running automated tests and tuning the difficulty. Checkpoints were not set in advance either.

Since staples showed no differences, the main run added "no testing" to the request to even out the conditions and raised the difficulty step by step.

Extras nobody asked for

Each request was a single sentence such as "Please build a falling-block puzzle game." What came back included many features that were never requested.

The falling-block puzzle had a next-piece preview, hold, sound effects and touch controls. Shogi had undo, a move record and repetition detection. The spreadsheet had cell formatting, row and column insertion, and CSV import and export. The desktop-style environment had eight apps, including a notepad, a calculator, a paint app and a minesweeper game.

This comes from the AI's own reports and from what was visible on screen. Whether each extra works correctly was not checked. Only the three checkpoints set in advance were.

The limit was not found

After all 15 passed, six harder subjects were drafted, including four-player mahjong with scoring, block-stacking physics and a puzzle with 50 stages that must all be solvable.

That plan was dropped. Laid side by side, it was hard to tell whether the subjects were really harder. The checking effort was also too large. A person cannot realistically confirm that all 50 stages can be solved.

Another idea was to fix one subject and only increase the number requested. That one had started to drift away from the original question.

So the experiment stopped here. It does not answer where an AI stops being able to build. What it shows is only that nothing broke within the range that was tried.

WHAT REMAINED

The checking side hit its limit first

In this experiment, Claude Code running Claude Opus 5.5 built 15 things from one-sentence requests with no testing. From a memory game to shogi that blocks illegal moves, a spreadsheet that calculates formulas, a 3D sandbox and a one-hour RPG, all 15 met the three checkpoints set in advance.

What did not go as assumed is which side reached its limit first as the difficulty rose. It was the checking side, not the building side. Building took minutes to tens of minutes. Confirming that a build is correct takes the time to play shogi to checkmate or an RPG to its ending.

There are clear limits on what this result supports. It used one model, built each subject once, had one judge and checked three points per build. The same request sent again would return something different. It does not show that AI can build anything in one attempt.

What can be said is that across 15 subjects, from staples to unreasonable ones, this experiment did not find the point where a one-sentence request breaks.
